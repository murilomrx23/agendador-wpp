Tudo que você precisa para dominar o Claude Code — do zero ao workflow profissional. Arquivos, comandos, organização e boas práticas.

🏠

O que é Claude Code?

Claude Code é a CLI oficial da Anthropic para usar Claude diretamente no terminal, dentro do seu editor ou via IDE. Diferente de um chat comum, o Claude Code tem acesso real ao seu projeto — lê arquivos, executa comandos, faz commits e entende o contexto do seu código.

🖥️

CLI no Terminal

Use diretamente no terminal com o comando claude em qualquer projeto.

🔌

IDE Extensions

Integração nativa com VS Code, JetBrains e outros editores populares.

🌐

Web App

Acesse via claude.ai/code diretamente no navegador.

☁️

Remote Execution

Execute em ambientes remotos isolados — ideal para CI/CD e automações.

ℹ️
Modelos disponíveis: Claude Opus 4.8 (mais poderoso), Sonnet 4.6 (balanceado) e Haiku 4.5 (mais rápido e barato). O Claude Code usa Opus por padrão para máxima qualidade.
⚙️

Instalação e Configuração

Instalar via npm

Requer Node.js 18+ instalado no sistema.

Autenticar com sua conta Anthropic

Execute claude e siga as instruções de autenticação.

Navegar até seu projeto

O Claude Code usa o diretório atual como contexto do projeto.

Iniciar uma sessão

Basta executar claude no diretório do projeto.

bash 
# Instalação global
npm install -g @anthropic-ai/claude-code

# Verificar versão instalada
claude --version

# Iniciar no seu projeto
cd meu-projeto
claude
✅
Dica: Use claude --dangerously-skip-permissions apenas em ambientes de teste isolados. Nunca em produção.
📁

Estrutura de Pastas

O Claude Code usa uma hierarquia de configuração em três níveis. Entender essa estrutura é essencial para personalizar o comportamento.

~/.claude/ ← Configurações globais do usuário
  settings.json ← Preferências globais (modelo, permissões)
  keybindings.json ← Atalhos de teclado customizados
  skills/ ← Skills customizadas globais

meu-projeto/
  CLAUDE.md ← 🔥 Contexto do projeto (MAIS IMPORTANTE)
  .claude/ ← Configurações específicas do projeto
    settings.json ← Permissões e hooks do projeto
    settings.local.json ← Configs locais (não comitar)
    skills/ ← Skills específicas do projeto
  src/
  package.json
  .gitignore ← Adicione settings.local.json aqui
⚠️
Atenção: Nunca comite .claude/settings.local.json no git. Ele pode conter tokens e configurações sensíveis.

Hierarquia de Configuração

As configurações são aplicadas na seguinte ordem (mais específico sobrescreve o mais geral):

1. Global (~/.claude/settings.json) → 2. Projeto (.claude/settings.json) → 3. Local (.claude/settings.local.json)
📄

CLAUDE.md — O Arquivo Mais Importante

O CLAUDE.md é automaticamente lido pelo Claude Code toda vez que uma sessão começa. É aqui que você define o contexto do projeto, convenções de código, comandos importantes e qualquer informação que o Claude precisa saber.

💡
Use /init para gerar um CLAUDE.md automaticamente com base no seu projeto. O Claude vai analisar a estrutura e criar um arquivo inicial.

Estrutura Recomendada

markdown 
# CLAUDE.md — Contexto do Projeto

## Visão Geral
App de chat em tempo real com React + Node.js.
Usa WebSockets para comunicação bidirecional.

## Comandos Essenciais
- `npm run dev`      — Inicia servidor de desenvolvimento
- `npm test`         — Executa suite de testes
- `npm run build`    — Build de produção
- `npm run lint`     — Verifica estilo de código

## Arquitetura
- Frontend: React 18 + TypeScript + Vite
- Backend: Node.js + Express + Socket.io
- Banco de dados: PostgreSQL com Prisma ORM
- Deploy: Cloudflare Workers

## Convenções de Código
- Use TypeScript strict mode
- Componentes React em PascalCase
- Hooks customizados prefixados com `use`
- Nunca use `any` — prefira `unknown`
- Testes com Vitest + Testing Library

## Estrutura de Pastas
- `src/components/`  — Componentes React reutilizáveis
- `src/hooks/`        — Custom hooks
- `src/lib/`          — Utilitários e helpers
- `src/types/`        — Definições TypeScript

## Coisas Importantes
- Sempre rodar `npm run lint` antes de commitar
- PRs precisam de pelo menos 1 revisor
- Variáveis de ambiente estão em `.env.example`

O que incluir no CLAUDE.md

  • ✓ Comandos de build, test e lint do projeto
  • ✓ Stack tecnológica e versões importantes
  • ✓ Convenções de nomenclatura e estilo de código
  • ✓ Estrutura de pastas explicada
  • ✓ Padrões de arquitetura específicos do projeto
  • ✓ Restrições ou regras especiais de negócio
  • ✓ Links para documentação importante
  • ✓ Informações sobre o ambiente de deploy

settings.json — Configuração Avançada

O arquivo .claude/settings.json controla permissões, hooks, modelo padrão e comportamentos automatizados do Claude Code no seu projeto.

json 
{
  "model": "claude-opus-4-8",

  // Permissões: ferramentas que o Claude pode usar sem perguntar
  "permissions": {
    "allow": [
      "Read",
      "Write",
      "Edit",
      "Bash(npm run *)",
      "Bash(git status)",
      "Bash(git diff)",
      "Bash(git log *)"
    ],
    "deny": [
      "Bash(rm -rf *)",
      "Bash(git push --force)"
    ]
  },

  // Hooks: comandos executados em eventos específicos
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          { "type": "command", "command": "echo Executando: $CLAUDE_TOOL_INPUT" }
        ]
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          { "type": "command", "command": "npm run lint --silent" }
        ]
      }
    ]
  }
}

Permissões Comuns

Permissão O que permite
Read Leitura de qualquer arquivo do projeto
Write Criação de novos arquivos
Edit Edição de arquivos existentes
Bash(npm *) Todos os comandos npm (padrão glob)
Bash(git status) Apenas o comando específico
WebFetch Buscar conteúdo de URLs externas
⚠️
Regra de ouro: Conceda apenas as permissões que o projeto realmente precisa. Use deny para comandos destrutivos como rm -rf e git push --force.

MCP Servers — Extensões do Claude

MCP (Model Context Protocol) permite conectar o Claude Code a ferramentas externas — bancos de dados, APIs, sistemas de arquivos remotos e muito mais.

json — ~/.claude/settings.json 
{
  "mcpServers": {
    // Servidor de banco de dados
    "postgres": {
      "command": "npx",
      "args": ["@modelcontextprotocol/server-postgres",
               "postgresql://localhost/mydb"]
    },
    // Servidor do GitHub
    "github": {
      "command": "npx",
      "args": ["@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_TOKEN": "${GITHUB_TOKEN}"
      }
    },
    // Servidor de arquivos local
    "filesystem": {
      "command": "npx",
      "args": ["@modelcontextprotocol/server-filesystem",
               "/caminho/para/pasta"]
    }
  }
}

Slash Commands — Comandos Rápidos

Os slash commands são atalhos que ativam comportamentos especiais. Use-os digitando / no início da mensagem.

Comandos de Projeto

Comando O que faz
/init Gera automaticamente o CLAUDE.md com base no projeto atual
/compact Compacta o contexto da conversa para economizar tokens
/clear Limpa o histórico da conversa atual
/review Revisa as mudanças do diff atual do branch

Comandos de Configuração

Comando O que faz
/config Abre o painel de configurações interativo
/model Altera o modelo para a sessão atual
/fast Ativa o Fast Mode (Claude Opus com output mais rápido)
/help Lista todos os comandos disponíveis

Comandos de Qualidade

Comando O que faz
/run Inicia e testa o app no ambiente local
/verify Verifica se uma mudança funciona conforme esperado
/code-review Revisão de código do diff atual com sugestões
/security-review Revisão de segurança das mudanças pendentes
✅
Skills customizadas: Você pode criar seus próprios slash commands criando um arquivo SKILL.md em .claude/skills/. O Claude vai carregá-los automaticamente quando relevante.
✍️

Como Escrever Prompts Eficazes

A qualidade da resposta do Claude Code depende diretamente de como você faz sua pergunta. Veja as diferenças práticas:

❌ Prompt vago
  • "Arruma o bug"
  • "Melhora o código"
  • "Faz um componente de login"
  • "Adiciona autenticação"
✅ Prompt específico
  • "Corrige o TypeError na linha 42 de auth.ts"
  • "Extrai a função validateEmail para um helper testável"
  • "Cria LoginForm com email/senha, validação e estado de loading"
  • "Adiciona JWT com refresh token em Express, salvo no httpOnly cookie"

Template de Prompt Eficaz

prompt 
# Estrutura recomendada para prompts complexos

Contexto: Estou trabalhando no componente UserProfile em src/components/UserProfile.tsx

Problema: O componente está re-renderizando desnecessariamente quando o usuário
digita no campo de busca — a prop user não mudou mas o componente re-renderiza.

O que preciso: Otimizar com useMemo/useCallback para evitar renders desnecessários.

Restrições:
- Manter compatibilidade com React 18
- Não quebrar os testes em UserProfile.test.tsx
- Usar os padrões de código do projeto (ver CLAUDE.md)

Dicas para Prompts Eficazes

  • Cite arquivos específicos: "no arquivo src/api/auth.ts, linha 87"
  • Descreva o comportamento esperado: "quando clicar em X, deve acontecer Y"
  • Mencione restrições: "sem quebrar os testes", "compatível com IE11"
  • Diga o que NÃO fazer: "sem adicionar dependências novas"
  • Peça etapas: "primeiro liste os arquivos afetados, depois faça as mudanças"
  • Use modo exploratório: "o que você mudaria aqui? não implemente ainda"

Workflow com Git

O Claude Code segue regras rigorosas ao trabalhar com git. Por padrão, ele pede confirmação antes de operações destrutivas ou visíveis para outros.

Operações Automáticas (sem confirmação)

bash 
# Leituras e inspeções — sempre automáticas
git status
git diff
git log --oneline -10
git branch

Operações que Pedem Confirmação

bash 
# Commits — Claude pede aprovação do usuário
git add src/components/Button.tsx
git commit -m "feat: add loading state to Button component"

# Push para remoto — sempre pede confirmação
git push -u origin feature/new-button

Operações que o Claude NUNCA faz sem permissão explícita

  • ✗ git push --force para main/master
  • ✗ git reset --hard sem confirmação
  • ✗ Deletar branches remotas
  • ✗ Amend de commits já publicados
  • ✗ Rebase destrutivo em branches compartilhados
💡
Mensagens de commit: O Claude Code gera mensagens seguindo o padrão tipo: descrição curta (ex: feat:, fix:, refactor:). Para personalizar, descreva o estilo no CLAUDE.md.
✅

Boas Práticas

1. Sempre Tenha um CLAUDE.md Atualizado

O Claude Code é tão bom quanto o contexto que você fornece. Mantenha o CLAUDE.md atualizado com mudanças na arquitetura, novos padrões de código e dependências importantes.

2. Seja Específico e Iterativo

❌ Evite
  • Pedir tudo de uma vez
  • Descrições vagas
  • Sem mencionar contexto
✅ Prefira
  • Dividir em tarefas menores
  • Descrever o comportamento esperado
  • Referenciar arquivos específicos

3. Use o Modo Exploratório Antes de Implementar

Antes de pedir mudanças, peça ao Claude para analisar e propor soluções. Isso economiza tempo e tokens.

prompt 
Modo exploratório — Claude analisa mas não modifica

"Analise o componente Auth.tsx e liste os problemas de performance
que você encontrar. Não implemente nada ainda, só me diga o que
mudaria e por quê."

4. Revise as Mudanças Antes de Aceitar

  • ✓ Sempre leia o diff antes de commitar
  • ✓ Use /verify para confirmar que a mudança funciona
  • ✓ Rode os testes após mudanças significativas
  • ✓ Verifique se arquivos não relacionados foram modificados

5. Controle o Escopo das Mudanças

✅
Princípio do mínimo necessário: Instrua o Claude a fazer apenas o que foi pedido. Sem refatorações não solicitadas, sem "melhorias" adicionais. Se quiser mais, peça explicitamente.
prompt 
Instruções de escopo no CLAUDE.md

## Regras de Modificação
- Altere APENAS o que foi solicitado
- Não refatore código não relacionado ao pedido
- Não adicione funcionalidades extras sem pedir
- Não mude testes existentes, a menos que solicitado

6. Gerencie o Contexto da Conversa

Conversas longas acumulam contexto e ficam mais lentas. Use /compact para comprimir o histórico ou /clear para começar do zero em novas tarefas.

Segurança

🚨
Nunca coloque segredos no chat! API keys, tokens, senhas e credenciais não devem ser digitados no chat. O Claude Code usa variáveis de ambiente — configure-as no seu sistema.

Proteção de Segredos

bash 
# ✅ Correto — use variáveis de ambiente
export ANTHROPIC_API_KEY=sk-ant-...
export DATABASE_URL=postgresql://...

# ❌ Errado — nunca faça isso no chat
# "Minha API key é sk-ant-abc123..."

O que Adicionar ao .gitignore

.gitignore 
# Claude Code — arquivos sensíveis
.claude/settings.local.json

# Variáveis de ambiente
.env
.env.local
.env.*.local

Permissões Seguras por Tipo de Projeto

Tipo de Projeto Permissões Recomendadas
Projeto pessoal / exploração Read, Write, Edit, Bash(npm *), Bash(git *)
Projeto de equipe Read, Edit, Bash(npm run *), Bash(git status/diff/log)
Ambiente de produção Apenas Read — sempre revisar manualmente
CI/CD Definir explicitamente por etapa do pipeline

Cuidado com Prompt Injection

Se o Claude estiver lendo conteúdo externo (arquivos de usuário, páginas web), esse conteúdo pode tentar manipular o comportamento do Claude. O Claude Code está treinado para detectar isso — se notar algo suspeito no output, questione antes de aceitar.

Dicas Avançadas

Agents Paralelos com Sub-tarefas

Para tarefas complexas, o Claude Code pode lançar sub-agentes em paralelo. Use o agente tipo Explore para pesquisas no codebase sem consumir o contexto principal.

prompt 
"Preciso refatorar o sistema de autenticação. Antes de fazer qualquer
mudança, faça uma análise completa de todos os arquivos que serão
impactados — use sub-agentes para verificar o frontend e o backend
em paralelo e me dê um relatório antes de começar."

Hooks para Automações

Use hooks no settings.json para automatizar tarefas que devem acontecer sempre que o Claude modifica arquivos.

json 
{
  "hooks": {
    // Roda lint após qualquer edição de arquivo TS/JS
    "PostToolUse": [{
      "matcher": "Write|Edit",
      "hooks": [{
        "type": "command",
        "command": "npx eslint --fix ${CLAUDE_TOOL_INPUT_PATH} 2>&1 | head -20"
      }]
    }],
    // Roda type-check ao parar de trabalhar
    "Stop": [{
      "hooks": [{
        "type": "command",
        "command": "npx tsc --noEmit && echo '✅ TypeScript OK'"
      }]
    }]
  }
}

Múltiplos CLAUDE.md (Monorepos)

Em monorepos, coloque um CLAUDE.md na raiz e também nas subpastas importantes. O Claude lê todos os relevantes para o contexto atual.

monorepo/
  CLAUDE.md ← Contexto geral do monorepo
  apps/
    web/
      CLAUDE.md ← Stack React específica
    api/
      CLAUDE.md ← Stack Node/Express específica
  packages/
    ui/
      CLAUDE.md ← Guia do design system

Modo de Confirmação Total

Para projetos críticos, configure o Claude para sempre pedir confirmação antes de qualquer mudança:

json — .claude/settings.json 
{
  "permissions": {
    "defaultMode": "ask",
    "allow": ["Read"],
    "deny": ["Bash(rm *)", "Bash(*--force*)"]
  }
}
